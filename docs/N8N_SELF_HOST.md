# دليل تفعيل n8n المستضاف ذاتيًا (لأحمد)

n8n الآن مستضاف على نفس خادم مسار Core، على الرابط:

**https://n8n.62.238.117.20.sslip.io**

## استيراد سير العمل (Workflows) — تلقائي بالكامل الآن

كل سير العمل الـء2١ (بما فيها **Job Bot - Admin Assistant** الكبير) تُستورد تلقائيًا
عبر سكربت تشغيل على المضيف (`deploy/ops/scripts/n8n-import.sh`، يُشغَّل من جلسة
Claude عبر أمر `script`) — لا حاجة لأي "Import from URL" يدوي بعد الآن. السكربت:

- يعيد تجميع سير العمل الكبير من الأجزاء المُقسَّمة ويتحقق من sha256.
- يتحقق من صحة JSON لكل ملف.
- يقارن بالاسم مع سير العمل الموجودة فعلًا داخل n8n (آمن للتكرار — لا يُنشئ
  تكرارات عند إعادة التشغيل).
- يستورد فقط الجديد عبر `n8n import:workflow` داخل الحاوية.

**كل سير العمل المستوردة تُنشأ INACTIVE (متوقفة) دائمًا** — هذا سلوك n8n CLI
الافتراضي، ومقصود: لا شيء يعمل فعليًا حتى تُفعّله أنت يدويًا بعد إعادة ربط
الاعتمادات (الخطوة التالية). فهرس **[n8n/workflows/INDEX.md](https://github.com/aborakanchatgpt-cloud/masar-core/blob/main/n8n/workflows/INDEX.md)**
يبقى مرجعًا مفيدًا لمعرفة اسم كل سير عمل، هل كان نشطًا في Cloud، والاعتمادات
المطلوبة له — فقط تجاهل روابط "Import from URL" فيه، فلم تعد مطلوبة.

بعد الاستيراد، اتبع الخطوات اليدوية التالية **بالترتيب**:

## 1) إنشاء حساب المالك (إن لم يكن قد تم بالفعل)
افتح الرابط أعلاه، وأنشئ حساب المالك (owner setup) بإيميلك وكلمة سر قوية إن لم
تكن قد فعلت ذلك. هذه الخطوة تُنفّذ مرة واحدة فقط.

## 2) إنشاء بيانات الاعتماد (Credentials)
افتح **https://n8n.62.238.117.20.sslip.io** ← Credentials ← Add Credential،
وأنشئ الاعتمادات التالية بنفس الأسماء المستخدمة داخل سير العمل المستوردة (n8n
يطابق الاعتماد باسمه، لذا الاسم يجب أن يكون مطابقًا تمامًا):

1. **Telegram API** باسم **"Telegram Admin Bot"** — توكن بوت الأدمن.
2. **Telegram API** باسم **"Telegram account"** — توكن بوت العميل (إن كان
   توكنًا منفصلًا عن بوت الأدمن).
3. **Gmail OAuth2** — سجّل الدخول بحسابك (لا تُدخل أي مفتاح يدويًا).
4. **Header Auth** باسم **"Masar Core Admin Token"**.
5. **Header Auth** باسم **"Masar GitHub"**.
6. **Anthropic API** باسم **"Anthropic account"**.

بيانات الاعتماد لا تُنقل تلقائيًا مطلقًا (ولا يمكن نقلها بأمان) — أنت تُدخل
القيم بنفسك مباشرة هنا، لا تُشاركها أو تُنسخها من أي مكان آخر.

## 3) إعادة ربط الاعتمادات داخل كل سير عمل
سير العمل استُوردت بأسماء الاعتمادات محفوظة لكنها **غير مربوطة** بمعرّف
اعتماد فعلي (n8n لا ينقل معرّفات الاعتماد بين الحسابات). افتح كل سير عمل
واحدًا تلو الآخر:

- أي عقدة تحمل علامة تحذير (⚠️) بسبب اعتماد مفقود → افتح العقدة ← أعد اختيار
  الاعتماد الصحيح من القائمة المنسدلة (سيظهر بالاسم الذي أنشأته في الخطوة 2).
- بعض سير العمل يستدعي سير عمل آخر بمعرّفه الداخلي (عقدة Execute Workflow) —
  هذه المعرّفات تغيّرت بعد الاستيراد. راجع القسم 4 في `INDEX.md` لمعرفة أي
  سير عمل يحتاج إعادة ربط، وأعد اختيار سير العمل الصحيح من القائمة يدويًا.

## 4) جداول البيانات (Data Tables) — يدوي دائمًا
جداول n8n Data Tables **لا** تُصدّر/تُستورد تلقائيًا بأي طريقة (لا عبر ملفات
JSON ولا عبر السكربت). أعد إنشاء بنية كل جدول يدويًا هنا حسب القائمة الكاملة
(الاسم، المعرّف الأصلي في Cloud، الأعمدة) في **القسم 3 من
[n8n/workflows/INDEX.md](https://github.com/aborakanchatgpt-cloud/masar-core/blob/main/n8n/workflows/INDEX.md)**،
ثم صدّر بيانات كل جدول من n8n Cloud كملف CSV واستورده هنا.

## 5) التفعيل (Activation) — بالترتيب، وليس دفعة واحدة
⚠️ **مهم جدًا قبل تفعيل أي شيء يتعلق ببوت تيليجرام**: بوت تيليجرام واحد لا
يمكن أن يخدم أكثر من ويبهوك (webhook) نشط في نفس الوقت. تفعيل سير عمل هنا
بينما نفس البوت مفعّل على n8n Cloud سيتسبب بتضارب (أحد الجانبين يتوقف عن
استقبال الرسائل بشكل عشوائي أو كليًا).

اتبع هذا الترتيب بالضبط:

1. **فعّل الجسور (Bridges) أولًا** — Core - Call، Core - Notify Admin، Core -
   Notify Customer، GitHub - Commit File، GitHub - Read File، HTTP - Probe.
   هذه لا تعتمد على أي شيء آخر ولا تستخدم بوتات تيليجرام الرئيسية، آمنة
   للتفعيل بمجرد التأكد من اعتماداتها.
2. **لا تفعّل أي سير عمل تيليجرام من "النظام القديم" (Legacy) هنا إلا بعد**:
   - إيقاف (deactivate) نفس سير العمل على **n8n Cloud** أولًا.
   - التأكد أن الويبهوك القديم على Cloud لم يعد مسجّلًا لدى تيليجرام (أو أنه
     سيُستبدل تلقائيًا فور تفعيل النسخة هنا).
   فعّل سير عمل واحدًا فقط، تأكد أنه يستقبل ويرسل بشكل صحيح (رسالة تجريبية)،
   ثم انتقل للتالي. لا تفعّل عدة سير عمل تيليجرام دفعة واحدة.
3. سير العمل غير المرتبطة بتيليجرام (Schedule، Webhook بدون بوت) يمكن تفعيلها
   بعد التأكد من اعتماداتها وجداول بياناتها مباشرة، دون قيد الترتيب أعلاه.

## 6) التبديل الفعلي (بعد التأكد من كل شيء أعلاه)
حوّل المهام المجدولة في Claude لاستخدام الموصل الجديد (self-hosted)، واستمر
بالاحتفاظ بحساب n8n Cloud فعّالًا كخط رجوع حتى تتأكد من استقرار كل شيء لفترة
كافية.

## 7) ملاحظة أمنية
مفتاح تشفير n8n (`N8N_ENCRYPTION_KEY`) يُولّد تلقائيًا ويُحفظ داخل
`/opt/masar-core/.env` على الخادم — لا تشاركه مع أحد ولا ترفعه لأي مكان.

## 8) وصول MCP (اختياري الآن)
موصل Claude **"Masar Core"** مفعّل بالفعل ويكتب/يقرأ من هذا المستودع مباشرة
عبر GitHub — لا تحتاج تفعيل MCP على مستوى نسخة n8n الذاتية لإتمام هذا الاستيراد
أو لتشغيل سير العمل. فعّل "Instance-level MCP" داخل n8n لاحقًا فقط إذا احتجت
أن يتحكم Claude مباشرة بسير عمل n8n (سرد/تشغيل) من نفس النسخة المستضافة ذاتيًا؛
هذه خطوة إضافية منفصلة وليست شرطًا لعمل النظام.
