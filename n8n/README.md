# n8n — وركفلوهات B5b (بوتا العميل والأدمن)

هذا الملف دليل المالك (أحمد) لتفعيل 5 ملفات الوركفلو الجديدة تحت
`n8n/workflows/masar_*.json` على نسخة n8n الذاتية
(`https://n8n.62.238.117.20.sslip.io`). نُفِّذت هذه الوركفلوهات وسُلِّمت
كملفات JSON قابلة للاستيراد فقط — **لا وصول لواجهة n8n أو لأي API فيها من
جلسة Claude التي بنتها**، فكل خطوة أدناه يدوية بالضرورة.

## 0. الاستيراد (منفَّذ تلقائيًا، لا حاجة لفعل شيء هنا عادة)

`deploy/ops/scripts/n8n_import.sh` يُشغَّل عبر `ops{cmd:"script", args:["n8n_import"]}`
ويستورد كل ملفات `n8n/workflows/masar_*.json` تلقائيًا (idempotent — إعادة
التشغيل تُحدِّث نفس الوركفلوهات بلا تكرار). كل الوركفلوهات المستوردة
**غير نشطة (Inactive)** دائمًا — السكربت لا يُفعّل شيئًا أبدًا. القسم 2
أدناه هو خطوة التفعيل اليدوية المطلوبة منك.

## 1. قائمة تحقّق المالك (NEEDS-OWNER) — نفّذها بالترتيب

1. افتح `https://n8n.62.238.117.20.sslip.io` وسجّل الدخول بحساب المالك.
2. أنشئ اعتماد Header Auth باسم **Masar Core Admin Token** بالضبط:
   الترويسة `Authorization`، القيمة `Bearer <التوكن>` — التوكن نفسه اقرأه من
   الخادم عبر: `ssh` أو من ops القياسي: (`grep CORE_ADMIN_TOKEN /opt/masar-core/.env`
   من طرفية الخادم مباشرة — لا تلصقه في أي محادثة Claude أو أي مكان آخر).
3. أنشئ اعتماد Telegram API باسم **Masar Customer Bot** بالضبط: توكن بوت
   "مسار" الحالي الذي يتحدث معه العملاء الآن (نفس بوت النظام القديم —
   من BotFather إن احتجت استرجاعه).
4. أنشئ اعتماد Telegram API باسم **Masar Admin Bot** بالضبط: توكن بوت إداري
   منفصل خاص بك وحدك (أنشئ بوتًا جديدًا عبر @BotFather إن لم يوجد بوت إداري
   مخصَّص بعد — **لا تستخدم نفس توكن Masar Customer Bot هنا**، حتى لا يرى
   العملاء أزرار لوحة التحكم بالخطأ).
5. أضف متغيّر بيئة n8n (Settings → Variables) باسم **MASAR_OWNER_CHAT_ID**
   بقيمة رقم معرّف محادثتك أنت على تيليجرام (chat id — أرسل أي رسالة لبوت
   Masar Admin Bot ثم اقرأ `message.chat.id` من `GET /admin/reports/pending`
   لا يفيد هنا؛ أسهل طريقة: أرسل `/start` للبوت الإداري بعد تفعيله لاحقًا
   وراقب تنفيذاته الفاشلة في n8n Executions — أول تنفيذ يُظهر `chatId` في
   عقدة "استخراج الدردشة"، انسخه كقيمة للمتغيّر، ثم أعد المحاولة).
6. تحقّق أن `n8n/workflows/masar_*.json` الخمسة مستوردة (Workflows → ابحث
   عن "مسار"): بوت الأدمن، بوت الأدمن (جزء 2)، تسليم التقرير اليومي، ردود
   الفعل 👎/🎉، تسجيل عميل جديد. **"بوت الأدمن (جزء 2)" يبقى غير نشط دائمًا
   عمدًا** — يُستدعى داخليًا عبر عقدة Execute Workflow من "بوت الأدمن"، ولا
   يحتاج تفعيلًا مستقلًا (Execute Workflow لا يشترط أن يكون الوركفلو المُستدعى
   نشطًا).
7. فعّل (Activate) **4 وركفلوهات** بهذا الترتيب بالضبط:
   1. **مسار - بوت الأدمن** (يستجيب فقط لمحادثتك أنت حسب MASAR_OWNER_CHAT_ID
      — آمن التفعيل أولًا لأنه لا يصل لأي عميل).
   2. **مسار - تسجيل عميل جديد** (onboarding) — يبدأ استقبال عملاء جدد فور
      التفعيل.
   3. **مسار - ردود الفعل 👎/🎉** (feedback) — آمن التفعيل الآن، الأزرار
      لن تظهر فعليًا حتى تُحلّ NEEDS-CORE #1 أدناه (لا تكسر شيئًا إن نشط الآن).
   4. **مسار - تسليم التقرير اليومي (19:00-21:30)** — فعّله **أخيرًا فقط**،
      بعد أن يوجد عميل واحد نشط على الأقل مربوط ببريد سليم (وإلا فلن يحدث
      شيء ضار، فقط لا فائدة من تفعيله مبكرًا).

## 2. مسار الاختبار (بعد التفعيل)

1. **بوت الأدمن:** أرسل أي رسالة لـ Masar Admin Bot من حسابك → يجب أن يظهر
   القائمة الرئيسية بالأزرار. جرّب "📊 نظرة عامة" و"📨 التقارير المعلّقة".
   أرسل رسالة من حساب تيليجرام **آخر غير حسابك** → يجب ألا يردّ البوت إطلاقًا
   (الحارس MASAR_OWNER_CHAT_ID يعمل).
2. **التسجيل:** من حساب تيليجرام تجريبي، ابدأ محادثة مع Masar Customer Bot
   → يجب أن يسير التسلسل: الاسم → المدن → المجالات (أزرار) → سيرة PDF →
   الموافقة → رسالة تحوي رابط `https://62.238.117.20.sslip.io/link/<token>`.
   افتح الرابط وتأكد أنه يعمل (نفس صفحة B5a المُختبَرة). تحقّق عبر
   `Core - Call`: `{"path":"/customers/<id>","method":"GET"}` أن العميل
   أُنشئ بـ`telegram_chat_id` صحيح.
3. **التقرير اليومي:** بين 19:00–21:30 بتوقيت الرياض، وللعميل التجريبي أعلاه
   (بعد أن يصير `status='active'` وله `telegram_chat_id`)، شغّل يدويًا عبر
   بوت الأدمن → "▶️ شغّل التقارير الآن"، ثم انتظر حتى الدورة التالية (≤5
   دقائق) للتسليم عبر تيليجرام، أو راقب Executions لوركفلو "تسليم التقرير
   اليومي" مباشرة.
4. **ردود الفعل:** لن تظهر أزرار 👎/🎉 فعليًا حتى NEEDS-CORE #1 (أدناه)، لذا
   تعذّر اختبارها حيًّا الآن — الوركفلو مستورد ومفعَّل وجاهز فور توفّر الحقل.

## 3. فجوات تحتاج تعديل Core (NEEDS-CORE) — خارج نطاق B5b (وركفلوهات n8n فقط)

1. **[الأهم] `daily_reports.payload.today_applications` لا يحمل أي معرّف
   لكل تقديم** (لا `id`، لا `send_queue_id`) — `reports.py:_fetch_today_applications`
   يُرجع فقط company/title/city/status. بلا معرّف، **لا يمكن بناء أزرار
   👎/🎉 فعليًا اليوم** — وركفلو `masar_daily_report_relay` مبني ليكون
   متوافقًا مستقبليًا: إن أضفتَ الحقل (مثلًا `a.opportunity_id AS send_queue_id`
   بربط `applications.opportunity_id = send_queue.opportunity_id` لنفس
   العميل، أو عمود `send_queue_id` جديد على `applications`) تظهر الأزرار
   تلقائيًا بلا أي تعديل بملفات n8n.
2. **لا نقطة نهاية لتحويل `telegram_chat_id` إلى `customer_id`.** الحل
   العملي المطبَّق: `customer_id` مُضمَّن مباشرة داخل `callback_data` نفسه
   (`fb:<customer_id>:<send_queue_id>:<kind>`) بدل استدعاء Core لحلّه — يعمل
   اليوم بلا أي تعديل مطلوب، لكنه يخالف الصيغة الحرفية `fb:<id>:<kind>`
   المذكورة بالتكليف الأصلي عمدًا لعدم وجود بديل. اقتراح مستقبلي لتوحيد
   الصيغة: `GET /admin/customers/by-telegram/{chat_id}`.
3. **لا نقطة نهاية لرفع سيرة PDF فعلية.** onboarding يخزّن معرّف ملف
   تيليجرام فقط بصيغة `cv_pdf_path = "telegram_file:<file_id>"` عبر
   `POST /customers/{id}/profile` — ليس مسارًا فعليًا وليس نصًا مُستخرَجًا.
   يحتاج لاحقًا نقطة تحميل حقيقية (تنزيل الملف من تيليجرام عبر بوت الأدمن أو
   Core نفسه، ثم استخراج النص لاستخدامه بمحرّك المطابقة B3).
4. **لا نقطة نهاية لتفعيل/إيقاف عميل.** بوت الأدمن يستدعي
   `POST /admin/customers/{id}/status {status}` وهي **غير موجودة اليوم بـCore**
   — الزر يعمل بالواجهة لكن يعيد رسالة اعتذار واضحة للمالك (لا يفشل بصمت).
   اقتراح: إضافة هذه النقطة بنمط `link_api.py`/`feedback_api.py` (تحديث بسيط
   `UPDATE customers SET status = :s WHERE id = :id` بقيمة من `{'active','paused'}`).
5. **تصميم متعمَّد يستحق مراجعة:** `customers.email_service` عمود
   `NOT NULL UNIQUE` بالمخطّط، لكن دليل §7 يجمع بريد Gmail الفعلي **بعد**
   إنشاء العميل (عبر صفحة `/link/{token}`، B5a). onboarding هنا يُنشئ العميل
   بقيمة مؤقتة فريدة `pending+<telegram_chat_id>@pending.masar.local` ثم
   الرابط الفعلي (mail_links.address) يُملأ لاحقًا بخطوة منفصلة تمامًا —
   لا يمس `customers.email_service` أبدًا بعدها. يعمل، لكن يستحق أن يقرّر
   الفريق التقني رسميًا هل هذا هو التصميم النهائي أم يُجعل العمود Nullable.

## 4. ملاحظات تنفيذ لم تُختبر حيًّا (بلا وصول n8n)

- عقدة الرد على استعلام الزر (`resource: callback`, `operation: answerQuery`)
  بُنيت اعتمادًا على معرفة مخطّط عقدة Telegram القياسية (بلا تحقّق تنفيذ حي
  فعلي عبر Telegram — لا وصول شبكي لبوتات حقيقية من بيئة البناء). تحقّق منها
  ضمن مسار الاختبار أعلاه؛ إن ظهر خطأ بشكل الحقول أبلغ المنفّذ التالي بنص
  الخطأ من Executions.
- تعبير `inlineKeyboard` الديناميكي (`={{ $json.keyboardRows ? {rows:...} : {} }}`)
  نمط شائع بوركفلوهات n8n المبنية برمجيًا، لكن لم يُختبر بتنفيذ فعلي هنا
  لنفس السبب. إن لم تظهر الأزرار رغم وصول `keyboardRows` بالبيانات (تحقّق من
  Executions)، أبدله بعقدة Set تبني القيمة الثابتة يدويًا لكل حالة.
